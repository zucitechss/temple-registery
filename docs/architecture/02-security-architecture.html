Security Architecture

Temple Registry · JWT RS256 + 3-Layer Authorization · 6 Roles · Source: security/*.java

Authentication Flow

1. User logs in at /api/v1/auth/login
2. If MFA enabled → temp token + verify at /mfa-verify
3. Receives access_token (15min) + refresh_token (7d)
4. Tokens stored in httpOnly cookies
5. Filter extracts and validates on every request

Authorization Layers

Layer 1: JwtAuthenticationFilter — sets SecurityContext
Layer 2: @PreAuthorize — role-based (SpEL expressions)
Layer 3: @DacvmGuard — policy engine (tightening only)
Layer 4: Service Guards — business rule enforcement

District Scoping

DC and DC_STAFF are jurisdiction-scoped via JWT districtId.

JurisdictionGuard traverses:
temple → hobli → taluk → district

Returns HTTP 404 (not 403) to prevent district enumeration.
